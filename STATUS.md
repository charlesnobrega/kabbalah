# Kabbalah Status

Kabbalah is an evolving research and engineering project.

This public status intentionally describes capability maturity at a high level. Detailed implementation state, internal architecture, security mechanisms, benchmarks, and development artifacts are maintained separately.

## Maturity labels

- **Operational** — capability exists in usable experimental form and is actively exercised.
- **Evolving** — capability exists but is being consolidated, redesigned, or expanded.
- **Experimental** — capability exists only in limited or early form.
- **Research** — direction is accepted as relevant, but is not yet part of the stable runtime.

## Current capability map

| Capability | Status | Public description |
|---|---|---|
| Govern | Evolving | User authority, policy, limits, accountability, and controlled execution are established concerns of the runtime and continue to be strengthened. |
| Reason | Evolving | Kabbalah supports multiple reasoning and orchestration approaches, but the long-term cognitive runtime is still being consolidated. |
| Act | Evolving | Controlled interaction with external tools and systems exists and is being hardened further. |
| Remember | Evolving | Persistent memory exists in experimental form; reliability, structure, revision, and consolidation remain active work. |
| Learn | Experimental | Runtime learning, evaluation, correction, and controlled improvement exist as partial capabilities and are being unified into a coherent learning model. |
| Share | Experimental | Cross-instance learning and federation exist in limited form and remain an active research and engineering area. |
| Robustness evaluation | Evolving | Security and containment testing exist, with broader comparative and adaptive robustness evaluation under development. |
| Autonomous evolution | Research / Experimental | Controlled self-improvement is a core direction, but promotion, evaluation, rollback, and invariant protection must mature before broader autonomy. |
| Parametric training | Research | Model-weight training is a separate future capability, not a prerequisite for Kabbalah's runtime learning model. |

## Current focus

The current phase is architectural consolidation.

Kabbalah accumulated several useful ideas and prototypes while the surrounding AI ecosystem evolved rapidly. The priority is now to unify those capabilities into one coherent system without discarding the project's strongest ideas or turning every new research result into another permanent subsystem.

The project is therefore focused on:

1. clarifying the durable identity of the runtime;
2. consolidating overlapping mechanisms;
3. improving memory and learning reliability;
4. strengthening resource-aware autonomy;
5. measuring robustness rather than relying on claims;
6. preserving the ability to absorb new research without architectural sprawl.

## What this status does not mean

A capability marked **Research** is not a promise of near-term delivery.

A capability marked **Operational** does not imply production certification.

Kabbalah remains an experimental project and public descriptions are intentionally more conservative than internal development goals.
