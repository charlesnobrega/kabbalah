# Repository Audit

Date: 2026-05-31
Branch: `chore/project-professionalization`

This audit treats source code and tests as the primary source of truth. Existing documentation is used only as historical context because several documents describe targets that are not fully implemented in runtime code.

## Current Architecture

### Agents

- `src/kabbalah/intake_node.py` implements request validation, run id generation, and specification generation.
- `src/kabbalah/root_orchestrator.py` defines domain branch decomposition and dependency-aware branch execution.
- `src/kabbalah/domain_orchestrator.py` defines leaf node spawning and leaf execution result objects.
- `src/kabbalah/synthesizer.py` consolidates branch artifacts into delivery packages.

Status: partially implemented. The classes and data models exist and have tests, but real leaf execution is still a placeholder: `DomainOrchestrator._execute_leaf_node()` returns success with empty artifacts and does not invoke providers or tools.

### Orchestration

- Tree shape exists: intake -> root -> domain -> leaf -> synthesizer.
- Branch and leaf identifiers are generated by runtime counters.
- Branch dependencies are resolved by domain name in `RootOrchestrator.execute_branches()`.
- Execution is sequential in the current implementation despite comments that describe future parallel execution.

Status: prototype/partially implemented. The orchestration skeleton is usable for structural tests, not for production multi-agent execution.

### Memory

- `src/kabbalah/memory_subsystem.py` defines `MemoryBackend`, `CogneeBackend`, `JSONLBackend`, and `MemorySubsystem`.
- JSONL storage is implemented with thread locking and substring search.
- Cognee import detection exists, but Cognee storage/query/consistency methods are placeholders.
- `src/kabbalah/memory_governance.py` provides category/operation access policies and audit logs.

Status: partially implemented. JSONL fallback is implemented; semantic retrieval through Cognee is not implemented beyond availability detection.

### Runtime

- `src/kabbalah/fsm_enforcement.py` models BOOTSTRAP/DAY1/DAY2 operation controls.
- `src/kabbalah/contract_enforcement.py` validates preconditions, postconditions, output parser results, and records violations.
- `src/kabbalah/role_trace_validation.py` checks role permissions and trace metadata consistency.
- `src/kabbalah/transition_validation.py` tracks agent health and DAY1-to-DAY2 transition checks.
- `src/kabbalah/day2_operations.py` models production operation constraints.

Status: implemented as in-process enforcement modules with tests. These modules are not yet wired as mandatory gates around every orchestrator/provider/tool operation.

### Providers

- `src/kabbalah/providers/base.py` defines the provider interface.
- Runtime provider factory supports `openai`, `google_gemini`, `groq`, `mistral`, `together`, and `deepseek`.
- `MockProvider` exists and is exported, but its constructor blocks usage unless `KABBALAH_ALLOW_TEST_FAKE_PROVIDER=1` is set.
- README still claims 12+ providers including Anthropic/Ollama/Replicate/Hugging Face/Azure, but the factory does not support that set.

Status: partially implemented. Six real provider adapters plus a gated fake provider exist. Provider claims in older docs are broader than runtime reality.

### Tools

- `src/kabbalah/tools/execution_engine.py` supports bash, file, grep, web, and MCP request types.
- Resource checks, retries, caching, and basic path/domain allow-lists exist.
- MCP execution is explicitly a placeholder returning an error that client configuration is required.
- Bash execution uses `shell=True`, so production use depends on strong policy and command review.

Status: partially implemented. Local tools exist; MCP is documentation-only in runtime behavior.

### Observability

- `src/kabbalah/observability/observability_module.py` stores traces, logs, and metrics in memory.
- `src/kabbalah/trace_id_tracking.py` defines hierarchical trace ids and execution logs.
- OpenTelemetry dependencies are listed in `requirements.txt`, but the runtime module does not export to OpenTelemetry/Jaeger/Prometheus.

Status: partially implemented. In-memory observability exists; external telemetry export is not implemented.

## Technical Debt

### Dead or Redundant Code

- Duplicate legacy package path: `kabbalah/error_detection_module.py` and `kabbalah/tests/...` exist alongside the `src/kabbalah` package.
- `tests/test_error_analysis_module_backup.py` appears to be a backup copy rather than a canonical test.
- Many root-level completion/status markdown files duplicate status narratives and make it hard to identify the current source of truth.

### TODOs and Incomplete Modules

- `DomainOrchestrator._execute_leaf_node()` is a placeholder and does not execute tools/providers.
- `MemorySubsystem.CogneeBackend` contains placeholder methods for semantic store/query/consistency.
- `ToolExecutionEngine._execute_mcp()` documents expected behavior but does not invoke an MCP client.
- OpenTelemetry/Prometheus dependencies are not wired to the observability module.
- Provider factory does not include all providers advertised by README and older specs.

### Broken or Risky Dependencies

- `requirements.txt` pins older provider SDKs; `google-generativeai==0.3.0` is documented in earlier audit notes as deprecated.
- Provider tests may require environment gates and real API credentials depending on selection.
- `cognee>=0.5.0` is optional in behavior but mandatory in requirements.

### Duplicated Logic

- Configuration logic exists in both `src/kabbalah/configuration_manager.py` and `src/kabbalah/providers/config.py`.
- Error models exist in both `self_healing.py` and `self_healing_models.py`.
- Documentation repeats phase and provider status across many root-level and `docs/specs` files with conflicting claims.

## Risks

### Architectural Risks

- The system presents a production-like architecture while critical execution paths are still prototypes.
- Enforcement modules are separate from orchestration paths, so governance can be bypassed by direct class usage.
- Provider selection is hard-coded in the root orchestrator for domains and not integrated with the provider factory.

### Scalability Risks

- Orchestration is sequential despite parallel-execution design goals.
- Memory JSONL backend rewrites the full file on every store operation.
- Observability is in-memory and bounded by local process lifetime.

### Governance Risks

- Conflicting documents make project status ambiguous.
- No current ADR directory existed before this branch.
- No current PR/issue template existed before this branch.
- No canonical roadmap separated implemented runtime from aspirational phases.

### Security Risks

- Tool execution uses `shell=True` and supports file deletion through the tool engine.
- Web access allow-list defaults to `["*"]`.
- Secrets loading exists in `secrets_vault.py`, but provider factories still read API keys directly from environment variables.
- Public provider exports include `MockProvider`, even though runtime policy disallows fake execution outside tests.

## Audit Conclusion

Kabbalah is best described as an alpha/prototype repository with strong test coverage around isolated modules and significant documentation volume. The repository is not yet a production multi-agent runtime. The next professionalization step should be governance consolidation and runtime integration of already-existing enforcement modules before adding new capabilities.
