# Kabbalah

**A sovereign runtime for autonomous intelligence.**

Kabbalah is being developed as a user-controlled environment in which AI systems can reason, act, remember, learn, evolve, and collaborate without transferring ultimate authority away from the user.

The project is not tied to a single model, provider, agent framework, or orchestration pattern. Models and external capabilities are treated as replaceable components inside a broader runtime whose identity is defined by durable principles rather than by whichever technique happens to be fashionable this quarter.

## Core idea

> **Capability may evolve. Authority may not self-expand.**

Kabbalah separates what an intelligent system **can do** from what it is **allowed to do**.

The long-term goal is a runtime that can improve from experience, question what it has learned, benefit from new research, and collaborate with other installations while keeping sovereignty, accountability, and control with the user.

## Six durable capabilities

### Govern

Maintain authority, identity, policy, limits, accountability, and user sovereignty.

### Reason

Use appropriate models, specialists, and reasoning strategies without binding the system to a single cognitive architecture.

### Act

Interact with tools and external systems through controlled and observable execution.

### Remember

Preserve useful long-term state while keeping memory revisable rather than treating stored information as permanent truth.

### Learn

Improve through experience, feedback, evidence, evaluation, and failure without automatically expanding authority.

### Share

Exchange validated knowledge or evidence between independent Kabbalah installations while preserving local sovereignty and privacy.

## Human guidance

Human-in-the-loop interaction is treated primarily as **guidance**, not as a substitute for technical safety.

The user may clarify intent, correct assumptions, select between legitimate alternatives, teach preferences, or redirect goals. Security should not depend on the user being a security expert or repeatedly approving prompts they may not fully understand.

## Learning without blind trust

Kabbalah is being designed around the assumption that learned information may be incomplete, outdated, biased, contaminated, or wrong.

Model confidence, stored memory, repetition, popularity, and inherited training data are not treated as equivalent to truth. Knowledge should remain open to evidence, contradiction, provenance, re-evaluation, and correction.

## Evolution and research

Kabbalah is intentionally research-permeable.

New research should be absorbed when it measurably improves an existing capability. A useful technique does not automatically deserve a permanent architectural layer, dependency, or subsystem of its own.

Techniques may change. The project identity should not.

## Robustness

Kabbalah treats robustness as something to **measure**, not merely claim.

Capability improvements should be evaluated together with resilience against loss of control, contaminated learning, unintended authority expansion, unsafe execution, excessive resource use, and other failure modes relevant to autonomous systems.

The project aims to improve capability and autonomy without making user sovereignty progressively weaker.

## Project status

Kabbalah is an evolving research and engineering project. Some capabilities already exist in experimental form, others are being consolidated, and others remain research directions.

The public repository is intentionally focused on the project vision, principles, status, and research direction. Detailed implementation, internal architecture, security mechanisms, and development artifacts are maintained separately.
